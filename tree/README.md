## BST 是什么？

**BST = Binary Search Tree（二叉搜索树）**，不是「二叉树」的简称。

| 概念 | 含义 |
|------|------|
| **二叉树（Binary Tree）** | 每个节点最多两个子节点，没有额外规则 |
| **二叉搜索树（BST）** | 在二叉树基础上：左子树 < 根 < 右子树 |

BST 是一种**带排序规则的二叉树**，用来支持相对高效的查找、插入、删除（树平衡时平均 O(log n)）。

## 节点字段

```go
type TreeNode struct {
    Val   int
    Left  *TreeNode
    Right *TreeNode
}
```

| 字段 | 作用 |
|------|------|
| `Val` | 节点上保存的**数据**（本实现为 `int`） |
| `Left` / `Right` | 指向左右子节点的**指针**，本身不存业务数据 |

插入、查找、删除时，都用「待处理的值」与 `node.Val` 比较，决定走左还是走右。

命名 `Val` 与 LeetCode 题目里的 `TreeNode` 约定一致。

## 为什么用树形结构？

- **普通二叉树**：不一定为了查找，也可表示层级、表达式等。
- **BST**：按大小组织数据，查找时每次比较后可排除一侧，不必像无序数组那样线性扫描。

| 操作 | 平均复杂度（树较平衡） | 最坏（退化成链） |
|------|------------------------|------------------|
| 查找 / 插入 / 删除 | O(log n) | O(n) |

若插入顺序很差（如一直插递增数），树会退化成链表。更完善的结构有 AVL、红黑树等。

## API 概览

| 方法 | 说明 |
|------|------|
| `Insert` | 插入值 |
| `Search` | 是否存在 |
| `Delete` | 删除值，返回是否找到 |
| `InOrder` | 中序遍历，返回升序 `[]int` |

```go
b := tree.NewBST(5, 3, 7, 1, 4)
b.Search(4)   // true
b.Delete(3)
b.InOrder()   // [1, 4, 5, 7]
```

## 删除节点

删除分三种情况（见 `deleteNode`）：

### 1. 无左子

直接用右子顶替当前节点（改指针，返回 `node.Right`）。

### 2. 无右子

直接用左子顶替（返回 `node.Left`）。

### 3. 左右都有（删「中间」节点）

**不是**把右子树的值依次往上挪，而是：

1. 在**右子树**里找**最小值**（一直 `Left` 到底）→ **中序后继（in-order successor）**
2. 将该值**复制**到当前节点的 `Val`（节点位置不变）
3. 在右子树里**删除**这个后继节点（它最多只有右子，易删）

示例：删除 `5`

```
        5                    6          ← 用右子树最小值覆盖 Val
       / \        →         / \
      3   7                3   7
         \ \                  \
          6 8                  8    ← 再删掉原来的 6
```

等价做法：用**左子树最大值**（中序前驱）替换亦可。本实现选用右子树最小值，是常见写法。

## InOrder（中序遍历）

`InOrder()` 遍历**整棵树**，把所有 `Val` 按顺序放入 `[]int` 返回。

遍历顺序：**左 → 根 → 右**。

在 BST 上，中序结果一定是**升序**，例如 `[1, 3, 4, 5, 7]`。

| 用途 | 说明 |
|------|------|
| 查看全部数据 | 一次性有序列出 |
| 测试 / 调试 | 插入、删除后验证树是否正确 |
| 验证 BST | 中序是否严格递增 |

复杂度：时间 **O(n)**；除结果切片外，递归栈约 **O(h)**（h 为树高）。

## 为什么叫 InOrder？

这是计算机领域的**固定术语**，全球通用（中文称「中序遍历」）。

| 遍历 | 顺序 | BST 中常见结果 |
|------|------|----------------|
| Preorder（前序） | 根 → 左 → 右 | 一般无序 |
| **Inorder（中序）** | 左 → 根 → 右 | **升序** |
| Postorder（后序） | 左 → 右 → 根 | 一般无序 |

*In* 表示根在左、右子树**之间**（in between），不是日常英语里的「在里面」。

觉得 `InOrder` 别扭很正常：它是**算法术语/黑话**，不是自然口语。在 LeetCode、教材、面试中 `InOrder` / `inorderTraversal` 非常常见。若更强调业务含义，也可用 `ValuesAscending` 等，但算法场景下 `InOrder` 一眼可辨。
